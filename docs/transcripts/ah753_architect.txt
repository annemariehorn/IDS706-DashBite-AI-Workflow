### 5. Risks and design concerns

- **Partial file reads:** producers write directly to final CSV/checkpoint filenames while consumers poll those directories. Containers preserve this existing race. Keep one instance of every stage; atomic publication could be a later improvement if verification exposes failures.
- **Persistent state changes restart behavior:** checkpoints, processed markers, and predictions survive container recreation. Document this and test it explicitly.
- **Dashboard health is limited:** an HTTP health check proves the dashboard responds, not that training or inference is progressing.
- **Startup takes time:** inference legitimately waits for enough features and the first checkpoint. Avoid treating that initial wait as failure.
- **Dependencies have open-ended minimum versions:** validate the selected Python/dependency combination; pin tested versions if reproducibility or compatibility requires it.
- **Storage grows continuously:** acceptable for this assignment, with a documented reset command.
- **Shutdown can interrupt writes:** direct foreground commands improve signal delivery, but they do not establish graceful completion of in-progress writes.
